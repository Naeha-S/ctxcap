The MCP Context Cost Index

Every MCP server a client connects sends its tool definitions in every session, before the model has been asked anything. The definitions are billed to the context window, and most people never see the bill. This page is the bill.

  • 16servers measured over stdio
  • 281tool definitions between them
  • 1,074tokens in the median server
  • 46,512in the largest, Sentry

This is not a ranking of quality. A server with 73 tools can do more than one with two, and a large schema is sometimes the honest way to describe a large API. What the table measures is what it costs to have that server switched on: tokens that sit in the context window for the whole session. A server nobody calls still pays.

The comparison column is against ctxcap's own server, which exposes four tools: measure, plan, verify, and trim. It exposes four tools and sits near the bottom of the table at 507 tokens. That is the point of the reference in the README: a server that answers four questions can cost 507 tokens, while one that answers many can cost 46,512 before it is asked anything.

Not measured

These are popular servers, but there is no honest single number for them. They are listed with the reason rather than dropped.

  • Supabase (@supabase/mcp-server-supabase@0.17.0) — Exposes no tools until a project is linked, so there is nothing to measure at startup.
  • Cloudflare (@cloudflare/mcp-server-cloudflare@0.2.0) — Requires a product name as a subcommand; there is no single default tool list.
  • Redis (@modelcontextprotocol/server-redis@2025.4.25) — Connects to Redis before answering initialize, so it does not start without a reachable database.

How it was counted

  • Each server was installed from npm at the version pinned in scripts/mcp-servers.json, started over stdio, sent initialize and tools/list, and stopped. No tool was called and no conversation was started.
  • The count covers name, description, and inputSchema for every tool. It leaves out title, annotations, and outputSchema, which some clients also send, so every number here is a lower bound.
  • Credentials were placeholders. tools/list is answered without a real token by these servers; an API call is not needed to learn what the tools cost.
  • Some servers can hide tools behind configuration or a selected toolset. The number is the default tool list, which is what a session pays before anyone tunes it. Sentry notes that it can be narrowed.
  • Tokens are counted with gpt-tokenizer@3.0.1, the same tokenizer as the The Context Budget Index. Other models tokenize differently, so read these as approximate and compare them with each other.
  • Servers that connect to a database before answering, expose nothing until configured, or require a product subcommand are in the list above, not silently absent.

What to do about it

The cheapest MCP server is the one that is not connected. The second cheapest is one that exposes the tools a session needs and no more: disable toolsets you do not use, and prefer a server that can return its tool list on demand rather than one that sends all 73 at startup.

npx ctxcap --compare     # your AGENTS.md, against the Context Budget Index
npx ctxcap init --agents mcp   # four tools, about 500 tokens
